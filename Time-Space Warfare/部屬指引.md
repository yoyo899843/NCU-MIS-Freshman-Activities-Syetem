# NCUMIS Camp 部署指引

給實際架設/更新伺服器時照著做的操作手冊。系統設計細節、資料庫 schema、API 設計請看 `PLAN.md`，這份文件只講「怎麼把它跑起來」。

## 系統架構總覽

五個獨立資料夾，各自一個 `docker compose` 專案，彼此不共用 DB：

| 資料夾 | 內容 | Host Port |
|---|---|---|
| `Portal/` | 玩家入口靜態頁（連結＋公告） | 9000 |
| `Time-Space Warfare/` | 時空戰爭遊戲主體（app + db） | 9001 |
| `PgAdmin/` | 全系統共用的資料庫管理介面，只給主辦本人用 | 9002 |
| `RPG System/` | 資管皇家學院數位探查儀（app + db） | 9003 |
| `Stock Game/` | 尚未開發，空資料夾 |  |

各系統的 `db` container 完全不對外，只有 app 跟 PgAdmin 會加入共用的 `ncumis-camp` 這個 external Docker network（給 Cloudflare Tunnel 連進來用）。

## 前置需求

- Docker Desktop（或 Docker Engine + Compose plugin）。
- Cloudflare Tunnel：**手動**在 Cloudflare dashboard 設定，本專案不包含 tunnel 設定檔。建議每個系統對應一個子網域（不要用路徑前綴），可避免 WebSocket 在路徑改寫時出問題。

## 首次部署

### 1. 建立共用網路（只需要做一次）

```bash
sudo docker network create ncumis-camp
```

### 2. 設定各系統的 `.env`

**有四個資料夾需要 `.env`，四個都要做，少一個那個系統就起不來。**

```bash
cd "Time-Space Warfare"
cp .env.example .env   # 編輯填入 POSTGRES_PASSWORD、JWT_SECRET

cd "../RPG System"
cp .env.example .env   # 編輯填入 POSTGRES_PASSWORD、JWT_SECRET（各系統各自獨立，不要共用同一組）

cd "../Stock System"
cp .env.example .env   # 編輯填入 POSTGRES_PASSWORD、JWT_SECRET

cd ../PgAdmin
cp .env.example .env   # 編輯填入 PGADMIN_DEFAULT_EMAIL、PGADMIN_DEFAULT_PASSWORD
```

`Portal` 和 `Mods` 是純靜態網頁，不需要 `.env`。

`.env` 不會進 git（已在 `.gitignore` 排除），密碼不要寫死進 `compose.yml`。

漏掉某個資料夾的 `.env` 時，那個系統的 `docker compose up` 會直接停下來並印出少了哪個變數（`compose.yml` 裡的 `${VAR:?...}` 就是在做這件事），不會建立任何容器。

### 3. 啟動順序

**`Time-Space Warfare`、`RPG System`、`Stock System` 都要先啟動，最後才啟動 `PgAdmin`**——PgAdmin 的 compose 需要引用這三個系統各自建立的 `timewarfare-internal`、`rpg-internal`、`stock-internal` network，順序反過來會找不到網路而啟動失敗。`Portal` 和 `Mods` 沒有依賴關係，順序不拘。

```bash
cd "Time-Space Warfare"
sudo docker compose up -d --build

cd "../RPG System"
sudo docker compose up -d --build

cd "../Stock System"
sudo docker compose up -d --build

cd ../Portal
sudo docker compose up -d

cd ../Mods
sudo docker compose up -d

# PgAdmin 一定要最後
cd ../PgAdmin
sudo docker compose up -d
```

這個順序跟 `.github/workflows/deploy.yml` 裡的迴圈一致，改動的話兩邊要一起改。

### 4. 資料庫 migration（自動，不用手動跑）

**container 啟動時會自己跑**，`migrations/` 底下所有 `.sql` 會依序套用，已套用過的自動跳過。

要確認有沒有跑成功，看 log：

```bash
sudo docker compose logs app | head -20
# applying: 001_init.sql
# migrations complete
# time-space-warfare listening on 3000
```

**migration 失敗的話 app 不會啟動**（container 會一直重啟）。這是刻意的——帶著錯誤的
schema 對外服務，比直接掛掉更難查。這種時候 `docker compose logs app` 會直接看到 SQL 錯誤。

需要手動跑的話（例如想先確認會套用哪些）仍然可以：

```bash
sudo docker compose exec app node migrations/migrate.js
```

### 5. 建立管理員帳號（+ RPG System 的學派帳號）

**管理員這一級是固定的**：沒有任何 HTTP 端點可以新增管理員、也不能把誰升成管理員，一律用伺服器上的 CLI script，**每個系統各自獨立一組帳號**。（關主帳號則可以由管理員在後台新增，見下面「權限分兩級」。）

```bash
docker exec timewarfare-app node scripts/create-admin.js <email> <密碼> "<顯示名稱>" [admin|gatekeeper]
docker exec rpg-app node scripts/create-admin.js <email> <密碼> "<顯示名稱>" [admin|gatekeeper]

# 範例：主辦（管理員，最後一個參數不填就是 admin）
docker exec timewarfare-app node scripts/create-admin.js admin@example.com a-strong-password "主辦"
# 範例：現場關主
docker exec timewarfare-app node scripts/create-admin.js gk1@example.com a-strong-password "關主小明" gatekeeper
```

**權限分兩級**（兩個系統都有）：

| | 管理員 admin | 關主 gatekeeper |
|---|---|---|
| 查看各種清單、戰況板 | ✅ | ✅ |
| Time-Space Warfare：改題庫、遊戲進程、重設 PIN、改陣營、戰況覆寫 | ✅ | ❌ |
| RPG System：改學派/關卡/線索/權限碼/科技樹/長老、遊戲進程、投票控制 | ✅ | ❌ |
| RPG System：幫隊伍標記關卡解鎖/完成、直接發線索給隊伍 | ✅ | ✅（後台「關主現場操作」頁） |
| 新增／重設密碼／刪除**關主**帳號 | ✅（後台「帳號管理」頁） | ❌ |
| 新增或調整**管理員**帳號 | 只能用 CLI | ❌ |

既有帳號在跑完 migration 之後**一律預設是管理員**，不會有人突然被降權。

活動當天要臨時多開關主帳號時，不用再回伺服器下指令：管理員登入後台 →「帳號管理」，填 email／密碼／顯示名稱就能新增，也可以在同一頁重設關主密碼或刪除關主。這一頁**只碰得到關主**——管理員那幾列只會顯示「固定帳號，只能用 CLI 調整」，就算自己直接打 API 也會被擋（403）。

已經留下操作紀錄的關主**不能刪除**（稽核會斷，API 回 409）。真的要停用他，改成「重設密碼」設一組沒人知道的密碼，帳號跟紀錄都留著、但登不進來。

同一組 email 再執行一次就是**重設密碼**（不是報錯），忘記密碼時直接重新執行這行指令就好。密碼建議至少 8 碼（script 本身會擋太短的密碼）。

`RPG System` 另外要建 **5 組固定的學派帳號**（活動當天隊伍直接用這組帳密登入，不是自行註冊）：

```bash
docker exec rpg-app node scripts/create-school.js <username> <密碼> "<顯示名稱>"

# 範例
docker exec rpg-app node scripts/create-school.js dragon-house a-strong-password "赤龍學派"
```

登入網址：`https://<你的網域>/admin/login.html`（各系統各自的網域/子網域）。

### 6. 下載地圖圖磚（有校園實際 GPS 座標之後再做）

`Time-Space Warfare/public/tiles/` 需要活動前手動下載好（自行 host，不連外部 tile server）：

1. 打開 `Time-Space Warfare/scripts/download-tiles.js`，把 `BBOX` 改成校園實際的經緯度範圍（9 個交摺點座標 + 一點邊界）。
2. 在有 Node.js 的機器上執行：
   ```bash
   cd "Time-Space Warfare"
   node scripts/download-tiles.js
   ```
3. 確認 `public/tiles/` 底下有東西之後，重新 build/部署讓新的圖磚一起進到 image 裡：
   ```bash
   docker compose up -d --build app
   ```

### 7. 設定 Cloudflare Tunnel（含預設 HTTPS）

在 Cloudflare dashboard（Zero Trust → Networks → Tunnels → 你的 tunnel → Public Hostname）手動設定，一個子網域對一個系統：

| 欄位 | 填法 |
|---|---|
| Subdomain | 例如 `game`、`rpg`（各系統各自一個） |
| Domain | 你掛在 Cloudflare 的網域 |
| Service Type | **HTTP**（不是 HTTPS） |
| URL | `localhost:<host port>`，對照上面的 Port 表（例如 Time-Space Warfare 填 `localhost:9001`） |

**重點：Service Type 選 HTTP、origin 端不用也不要裝 TLS 憑證。** Cloudflare Tunnel 的加密是在 `cloudflared` 到 Cloudflare 邊緣節點這段，跟 app 本身講不講 https 無關；app（Express）維持現在這樣單純聽 HTTP 就好，不用在 container 裡另外處理憑證。

要讓外部訪客**預設走 https**（例如直接打 `http://` 網址也會自動導向 `https://`），是在 Cloudflare 的**網域設定**裡開，跟 Tunnel 設定是分開的兩個地方：

1. 進你的網域 → **SSL/TLS → Edge Certificates**，把 **Always Use HTTPS** 打開。這樣任何人打 `http://你的網域` 都會被 Cloudflare 自動 302 導到 `https://`。
2. 同一頁可以順便打開 **Automatic HTTPS Rewrites**，避免頁面裡不小心寫死 `http://` 連結造成混合內容警告。
3. **SSL/TLS → Overview** 的加密模式（Flexible/Full/Strict）主要是給「Cloudflare 邊緣 → 你的 origin」這段用的，Tunnel 情況下 origin 是走 `cloudflared` 出去、本來就已經是加密的，這個模式選預設的 Flexible 就好，不用特別調。
4. Public Hostname 存起來的時候，Cloudflare 會自動幫這個子網域簽發憑證（Universal SSL），不用手動申請/上傳。

**為什麼一定要 https（不只是安全考量）**：Time-Space Warfare 跟 RPG System 的 GPS 圍籬、相機掃 QR Code 這些功能都要呼叫瀏覽器的 `navigator.geolocation` / `getUserMedia`，這兩個 API **只有在「安全情境」（https，或 localhost）下才會被瀏覽器允許使用**。本機用 `localhost:900x` 開發測試沒問題，但正式上線一定要透過上面設定好、`Always Use HTTPS` 開著的網域訪問，不能只用 `http://<伺服器IP>:900x` 這種方式直接測，不然相機/定位會直接被瀏覽器擋掉。

## 更新部署（程式碼有異動之後）

```bash
cd "Time-Space Warfare"
git pull                          # 或其他方式把新程式碼弄到伺服器上
docker compose up -d --build app  # 重新 build image、重啟 container（會自動跑 migration）
```

新的 migration 會在 container 啟動時自動套用，不用再手動跑。更新後看一下
`docker compose logs app` 確認有 `migrations complete` 就好。

`RPG System`、`Stock System` 都是同樣的流程（在各自的資料夾下執行）。`Portal`、`PgAdmin` 通常不太會變動，但如果有改也是同樣的 `docker compose up -d --build` 流程。

## 活動當天的操作順序（時空戰爭）

陣營是在按下「開始遊戲」的那一刻抽的，不是玩家登入時分配的。所以順序不能顛倒：

1. **先讓所有隊伍登入**（玩家端 `/login.html`，代號＋4 碼 PIN）。還沒登入的隊伍不會被抽到。
2. 管理後台 → 遊戲進程控制 → 設定「破壞者（內鬼）隊伍數」（企劃是 3）。
3. 按「**開始遊戲（同時抽陣營）**」。系統隨機抽出指定數量的破壞者，其餘都是時空保衛隊；每台手機會自己跳出彈窗顯示身分。至少要留一支保衛隊，隊伍數不足會被擋下並告訴你還差幾支。
4. 中途要重來：再按一次「開始遊戲」就會**重抽**，所有人的身分都會換掉（會先跳確認）。
5. 遊戲結束前開「最終審判」投票，投完關閉。誰是內鬼在管理後台的「投票結果」頁看得到——**那一頁不要投影出去**。

**換一梯次、要把資料全部清空**：管理後台最下面的「重啟遊戲」卡片，輸入 `RESET` 再按按鈕。會刪掉所有隊伍與玩家帳號、關卡紀錄、PK、任務、筆記、投票，並把據點進度歸零；交摺點本身、題庫、管理員/關主帳號、稽核紀錄都會保留。重啟後玩家要重新登入建立隊伍。

## 常見問題

**`error: relation "xxx" does not exist` 或 `column "xxx" does not exist`**
Migration 沒套用成功。因為 migration 現在是啟動時自動跑的，這通常代表 app 根本沒起來——
用 `docker compose ps` 看是不是在 restarting，再用 `docker compose logs app` 看實際的 SQL 錯誤。

**忘記 admin 密碼**
重新執行「首次部署 步驟 5」的 create-admin 指令，同一個 email 會直接覆蓋密碼。

**按了「開始遊戲」卻說隊伍不夠**
抽陣營至少要留一支時空保衛隊，所以隊伍總數必須比破壞者數多至少 1。先讓還沒登入的隊伍登入，或把「破壞者隊伍數」調低。

**玩家的畫面顯示「陣營未公布」**
還沒抽籤。要按過「開始遊戲」才會抽，抽完玩家端會自己跳彈窗（最多等 5 秒）。

**某支隊伍刪不掉**
有比賽紀錄的隊伍預設擋下來，因為他打過的 PK 也是對手的勝場，刪掉會讓對手的積分跟著少。確認過就在跳出來的第二次確認按下去，會連紀錄一起刪。要整批清空請用「重啟遊戲」。

**PgAdmin 啟動失敗（連不到 network）**
確認 `Time-Space Warfare`、`RPG System`、`Stock System` 都已經先啟動過（會分別建立 `timewarfare-internal`、`rpg-internal`、`stock-internal` network），再啟動 `PgAdmin`。

**`dependency failed to start: container xxx-db is unhealthy`**
幾乎都是那個資料夾少了 `.env`。缺 `POSTGRES_PASSWORD` 的話 postgres 會拒絕初始化、容器一起來就退出，而 compose 只會回報「unhealthy」，不會告訴你少了檔案。

到那個系統的資料夾下 `cp .env.example .env` 填好內容再重跑即可（現在 compose 會在建立容器前就擋下並指出少了哪個變數，不會再出現這句誤導的訊息）。

如果 `.env` 補好了還是 unhealthy，代表 volume 裡留著上一次失敗的半殘資料，先看 log 確認：

```bash
docker compose logs db          # 看 postgres 真正的錯誤
docker compose down             # 注意：加 -v 會連資料一起刪，正式環境不要亂加
```

**想查某支隊伍的 PIN 碼**
PIN 是明碼存在資料庫（刻意不雜湊，方便隊輔忘記時查詢），用 PgAdmin 連進 `timewarfare` 資料庫查 `players` 表的 `pin` 欄位即可。admin 密碼、RPG System 的學派密碼則相反，是雜湊過的，查不到明碼，只能重設。

**忘記 RPG System 學派帳號密碼**
重新執行「首次部署 步驟 5」的 create-school 指令，同一個 username 會直接覆蓋密碼。

| 動作 | 指令 |
|---|---|
